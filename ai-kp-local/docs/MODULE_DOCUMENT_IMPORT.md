# KP 本文档导入边界

## 当前实现

第六版来源结构链路已经落地：

- 独立 `/modules` 页面接受 PDF/DOC/DOCX，展示持久任务、失败原因、重试、模组版本、
  章节正文与内嵌图片。
- 接收阶段只在主进程校验白名单扩展名、PDF/ZIP 文件签名和原始大小；DOCX 成员数量、
  解压后总大小、XML 大小、危险实体声明，以及 PDF 页数、解压后页面内容流、
  图片数量/字节/像素，全部在隔离解析进程内校验。
- PDF 与 DOCX 的正常导入统一调用本地 MinerU；旧 `.doc` 在同一隔离边界先转为 DOCX，
  然后仍调用 MinerU。项目内置解析器仅通过 `AI_KP_MODULE_DOCUMENT_PARSER=builtin`
  显式启用作故障恢复，不会在 MinerU 失败时静默切换。
- PDF/DOC/DOCX 图文解析不在 API 或 worker 主进程内执行。每次尝试都通过 `spawn` 启动
  可终止的独立子进程，并受墙钟超时约束；POSIX 平台另外设置地址空间和 CPU 时间
  `rlimit`，不支持该能力的平台仍由墙钟超时与解析器硬上限保护。压缩文件即使宣称
  很小，也必须在文字提取前通过解压后内容流上限。
- `module_import_jobs` 保存任务和重试次数；源文件先按哈希写入私有存储。完成时，
  模组、文本块和图片元数据在一个 SQLite 事务中提交，失败不会留下半个模组。
- MinerU 的 `content_list.json` 是稳定归一化入口，并与 `middle.json` 的段落样式在数量
  一致时对齐。PDF 保留 `mineru:page:*:block:*` 页码锚点；Office 文档保留稳定块顺序，
  但 MinerU 当前不保证 Word 原始页码。重复图片共享同一个内容哈希文件，每次出现仍有
  独立来源记录。
- 文本块还保存确定性结构类型、置信度、Word 字符样式和待审查标记；当前识别标题、
  模组元数据、KP 概要、场景、线索、普通/SAN 检定、数据块、展示材料、结局和可选
  分支。这些提示只用于导航，不能替代原文证据。
- 图片保存地图、展示材料、肖像、场景插图、预设调查员、装饰图或未知类型候选；
  PDF 中不超过 32×32 的装饰字形不会污染正式素材库。
- PDF 在页码锚点不变的前提下按标题和段落边界细分，避免把整页不同功能内容交给
  同一次 AI 提取。
- 图片默认 `kp + pending_analysis`。KP Bearer 权限同时保护列表和原图内容接口；
  玩家不能直接读取。源文件和图片已进入完整备份/离线恢复。
- `module_import_jobs` 是权威队列；应用 lifespan 启动一个使用独立 SQLite 连接的单机
  worker，自动领取既有 `queued` 任务。意外停在 `processing` 的任务会在启动时提交为
  `queued` 并自动重跑；每次领取递增 `attempt_count`，所有进度、失败和原子完成写入
  都用该代次 CAS，旧 worker 不能留下重复模组。正常关闭会停止领取新任务并等待当前
  任务完成。隔离解析失败仍按同一 `attempt_count` 写入失败原因，KP 可沿用原重试
  入口；HTTP 请求不再依赖 FastAPI 请求内 `BackgroundTasks` 执行解析。
- KP 可按章节设置 `player/table/kp/secret` 与剧透标签；文本、图片 OCR、视觉摘要和
  已批准知识共享同一权限过滤检索入口。
- 候选知识必须继承引用文本/图片的可见性与剧透标签；实体和关系只能进一步收紧，
  不能降级。检索会再次核对候选、两端实体和关系的全部来源范围，以便旧数据也
  fail-closed。
- KP 修改章节可见性或剧透标签时，所有引用该章节文本块或图片的已批准候选都会
  原子退回 `pending`，并清除旧审核人、审核时间和审核意见。依赖这些候选的实体与
  关系保留 provenance 记录，但在候选重新通过当前来源校验前不会进入有效上下文、
  KP 图谱列表或剧情锚点可达性遍历。
  旧候选不能直接重复批准；审核动作会重新检查每条引文仍存在、证据仍匹配，并确认
  候选没有放宽任何当前来源的可见性或剧透范围。
- 搜索和 AI 上下文在每次读取时还会独立解析所有 citation 指向的当前 chunk/asset
  范围；来源缺失、跨模组、权限不兼容、调用者不可见或剧透尚未解锁时一律拒绝派生
  候选及其图谱。KP 图谱列表与可达性检查同样逐次重验候选、实体、关系和两端实体
  的当前 provenance；失效记录只从有效视图中过滤，不会删除审计数据。这遵循
  OWASP Authorization Cheat Sheet 的
  [默认拒绝、最小权限和逐请求权限校验](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
  原则，不能把提取或首次审核时保存的候选 ACL 当作长期授权缓存。
- 本机 Tesseract 是可选 OCR 适配器，启动时报告实际可用语言；缺少 `chi_sim` 时不会
  假装支持中文。OpenAI-compatible 多模态接口接收 data URL，并被明确要求把图片当作
  不可信证据、不得执行图中指令。
- AI 只能生成结构化知识候选。每条引文必须逐字存在于所属文本块或图片派生文本中，
  且来源必须属于当前模组；只有 KP 批准后才进入检索索引。
- 模组知识抽取若在 LLM 返回前中断，应用重启会把 `processing` 文本块退回
  `pending`；已完成和显式失败记录保持不变。每次领取都会原子递增文本块的
  `attempt_count`。LLM 返回后，候选写入与完成状态在同一个短 SQLite 写事务内校验
  `processing + attempt_count`，因此恢复前的旧 worker 不能向新领取代次写入候选或失败。
  若短事务的开始、候选写入或提交发生意外 SQLite 错误，服务会先回滚局部结果，再尽力
  以同一代次 CAS 标为 `failed`，无需重启即可由 `retry_failed=true` 重试。
- `campaign_module_runs` 显式记录每团当前使用的模组、场景、已解锁剧透标签和小型
  结构化进度快照。每团最多一个 `active` 运行；启动同一模组是幂等操作，不会因重试
  清空进度。所有修改都携带 `expected_version`，并发冲突返回 `409` 后必须刷新。
- 运行态编码后最多 4 KiB，只保存当前桥接状态、已触发锚点等短小进度；长期事件、
  NPC 经历和角色主要/支线记忆仍进入各自的权威时间线，不能塞入运行态 JSON。
- AI 上下文只读取活动运行对应的模组和已批准知识。没有活动运行时，单模组兼容分支
  只供 KP 过渡使用；玩家作用域不能通过请求参数自行解锁剧透。

尚未实现的是页面坐标、缩略图和 OCR 人工校订。实体关系图谱与剧情
锚点可达性检查已经存在；所有派生结构仍不能覆盖原始图文证据。

## Steam 分发与可选依赖边界

MinerU 是离线导入/作者能力，不是游戏结算依赖。Steam 基础客户端和加入房间的玩家只需
读取已经归一化、版本化并通过权限检查的模组产物；不得捆绑 MinerU、Torch、版面模型或
OCR 权重。房主没有安装导入工具时，仍可创建/加入游戏和加载预处理模组，只是不能在本机
重新解析 PDF/DOCX。

推荐拆成三个可独立发布的组成部分：

1. `AIKP Runtime`：游戏核心、SQLite、规则插件与已有索引。
2. `AIKP Host Tools`：导入任务 UI、队列与通用文档解析端口。
3. `AIKP MinerU Importer`：可选下载的 MinerU 进程、模型权重和 GPU/CPU 后端。

Importer 输出固定的产物协议（版本化 manifest、结构化内容、素材及来源坐标），Runtime
只验证并导入该协议。当前 `extract_mineru_document` 已经只读取 MinerU JSON/图片而不
import MinerU，适合作为迁移期间的兼容适配器；真正需要从 Runtime 分离的是
`mineru_parser` 的进程启动和重量级安装环境。拆分前必须保留现有压缩包路径、大小、页数、
进程超时和来源哈希校验，不能以减依赖为由把不可信文档解析移回游戏主进程。

## 用户入口

面向 KP 的导入页面只接受：

- PDF（`.pdf`）
- 旧式二进制 Word（`.doc`，需要本机 LibreOffice Writer）
- Word Open XML（`.docx`）

旧式 `.doc` 在 API 主进程只检查 OLE CFB 签名与 64 MiB 上限；原始字节先进入私有
内容寻址存储，任务的 `source_hash` 始终是原始 `.doc` 的 SHA-256。实际转换只发生在
现有 spawn 解析子进程中：以参数数组而非 shell 调用可配置的 LibreOffice `soffice`，
使用独立临时 `UserInstallation`、`--headless`、`--norestore`、转换超时和独立进程组。
stdout/stderr、转换产物大小和 ZIP 签名均有上限；外层解析超时还会清理已记录的转换器
进程组。转换后的临时 DOCX 随后完整经过与原生 DOCX 相同的成员数、展开大小、安全 XML、
图片与文本限额，成功或失败后连同临时 profile 一起删除。数据库继续规范化保存
`source_type='docx'`，当前 `parser_version=module-document.v6`。v6 将 MinerU 标题、正文、
列表、表格、图片和图注归一化到同一来源契约，并让未被更强语义覆盖的普通段落继承
“结局/展示材料/预设角色”等强章节语义，避免只识别标题而漏掉正文。

生产默认值为 `AI_KP_MODULE_DOCUMENT_PARSER=mineru`、`pipeline` 后端和本地模型源；
`AI_KP_MINERU_COMMAND` 只接受可执行文件名或绝对路径，不接受 shell 参数。大型扫描 PDF
可能需要数十分钟，因此文档导入使用独立的 `AI_KP_MODULE_DOCUMENT_PARSE_*` 预算，
默认墙钟/CPU 为 10800 秒、地址空间预算为 8192 MiB；规则书仍使用较短的
`AI_KP_MODULE_PARSE_*` 预算。超时会终止完整 MinerU 进程组并保留可重试任务语义。
每次导入会启动一个受限的本地 `mineru-api` 进程，并直接使用其任务接口；任务报告完成后
仍会在总超时内重试结果包，以兼容结果归档稍晚就绪的情况。超过 48 页的 PDF 会按连续
页范围复用同一个 MinerU 后端，再由服务器重写全局页码、块序号并继承跨段标题，不会把
分段边界暴露成不同模组或改用另一套解析器。模式识别的预扫描最多均匀抽取 12 页判断
使用文本还是 OCR，但仍会遍历全部页面检查解压内容流预算。

LibreOffice 未安装、命令配置错误、转换超时、退出失败或产物无效都会成为可重试任务的
明确错误，不会回退到主进程解析。真实样本仍可能因转换改变字体和图片锚点，KP 应在
导入后对章节与图片进行人工核对。图片文件不作为独立 KP 本上传，但 PDF/DOC/DOCX 内嵌的
照片、地图、扫描线索和插图必须被保留。

## 结构设计依据

- Chaosium 的 Miskatonic Repository 创作建议要求尽早向 KP 说明真相，并避免只有
  单一获取方式的线索瓶颈。因此结构化结果必须区分 KP 概要、线索和剧情锚点，并在
  图谱阶段检查多路径可达性。
- Foundry VTT 的 Adventure Document 将冒险表示为 Actors、Scenes、Items、Journal
  Entries、Roll Tables 等保持链接的内容包。本项目采用相同的“多类型且可链接”原则，
  但增加严格的原文引用、剧透隔离与 KP 审批。

现有纯文本模组 API 是内部切块与权限基础，不代表最终产品允许上传 TXT、Markdown、
HTML 或其他文件。

## 导入产物

一次导入产生一个不可变来源版本，并拆成两类相互关联的资产：

1. 文本块：正文、标题层级、表格文字、页码或段落范围。
2. 图片资产：原始图片字节、媒体类型、尺寸、来源页码或 DOCX 锚点、附近标题与图注。

OCR 和视觉摘要是可重建的派生数据，不能替代原图。每个派生结果必须记录解析器版本、
模型 ID、生成时间和对应图片哈希。

文本和图片解析完成后，AI 可以提出结构化知识候选，但不能直接宣布为事实：

- `module_canon`：模组明确给出的真相、人物、地点和约束。
- `module_anchor`：必须保持可发现或可参与的关键线索、冲突和叙事功能。
- `reference`：背景说明、气氛、例子和可选素材。

所有候选都保留原始 chunk、图片、页码或 DOCX 锚点，由 KP 审核后进入模组知识层。
`module_anchor` 表示保持叙事功能可达，不表示必须在固定场景、固定时间强制发生。

## 图片处理

处理顺序：

1. 安全校验文件签名、压缩包展开上限、页数、总像素和单图大小。
2. 提取原图并计算稳定哈希；重复图片只存一份，但保留所有出现位置。
3. 对包含文字的扫描件运行 OCR。
4. 可用多模态模型时生成客观视觉摘要，例如人物、场所、线索物件和地图类型。
5. 没有 OCR 或视觉模型时，将图片标记为 `pending_analysis`，整本文档仍可完成导入。
6. KP 在正式入库前预览并修正标题、章节、图片说明和秘密范围。

视觉理解不能自行宣布规则事实或剧情真相。它只生成候选描述，由结构化导入流程和 KP
确认后进入可检索知识。

## 剧透与访问控制

- 文本块与图片默认继承所在章节的可见性和剧透标签。
- 图片 OCR、图注和视觉摘要继承原图权限，不能因成为“搜索文本”而放宽访问。
- 玩家接口不能返回未揭示图片的元数据、缩略图、OCR 文本或存在性线索。
- AI KP 检索结果必须携带来源位置和可见性，不能把未来章节自动加入当前上下文。
- 模组运行的读取、启动和修改接口仅限该团 KP；前端玩家视图不请求也不缓存运行态。

## Real-case 验收

每阶段都使用含正文、章节标题、表格、普通照片、扫描手写线索和地图的 PDF、DOC 与
DOCX 测试：

1. 上传预检：拒绝伪装扩展名、超限文件和不受支持的格式；合法 `.doc` 仅在
   LibreOffice 可用时进入隔离转换，缺少转换器会留下明确可重试失败。
2. 文本解析：章节顺序、页码/段落锚点和表格内容可追溯。
3. 图片提取：原图、缩略图、重复引用和附近图注正确。
4. 无视觉模型：导入成功，图片显示待解析。
5. 有视觉模型：OCR/摘要保存模型来源，重新分析不会覆盖原始证据。
6. 权限验证：玩家无法通过列表、搜索、直接资源地址或实时事件发现秘密图片。
7. 重启恢复：来源文件、解析版本、图文关系和 KP 修订均能恢复。
8. 队列恢复：服务在 `queued` 与 `processing` 两个阶段中断后，重启均能自动完成，
   且 `attempt_count` 可审计。
9. 恶意压缩流：约 20 KiB 的 PDF 若解压出超过 16 MiB 的单页内容流，应快速失败，
   API/worker 主进程保持健康，并允许按原任务语义重试。
10. 合集边界：含多个显式 Chapter/章节的文件应同时提供整本与逐章来源范围；生成契约前
    必须由 KP 选择。普通“场景 1/2”或纯数字小节仍属于同一个剧本，不能被拆成多本。
11. 数据库健康：大文件导入后同时运行 SQLite 与 FTS5 完整性检查；全文索引损坏必须让
    诊断/备份验证失败，并可在不改动原始 KP 本的前提下重建索引。

旧版内置解析器产生的真实附件计数只作为迁移基线，不再代表生产导入结果。验收必须先以
MinerU 重新导入每个去重后的真实模组，再从 UI 选择来源范围、生成全 AI KP 契约并完成
实际行动；不得复用旧解析结果冒充 MinerU 验收。旧 DOC 数据库仍规范化保存
`source_type='docx'`，但 `source_hash` 必须始终对应原始 `.doc` 字节。

模组知识和运行世界的权威关系见
[`WORLD_EXPANSION.md`](WORLD_EXPANSION.md)。
